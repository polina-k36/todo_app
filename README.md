# Todo App

Full-stack приложение для управления личными задачами, разработанное как учебный и портфолио-проект.

Проект состоит из двух частей:

* **Frontend** — клиентское приложение на React.
* **Backend** — REST API на NestJS.

Приложение позволяет пользователям управлять задачами и категориями, отслеживать прогресс, работать с профилем и использовать защищённую JWT-аутентификацию.

## Аутентификация на клиенте

Для управления состоянием авторизации используется:

```text
AuthContext
        ↓
AuthProvider
        ↓
useAuth()
```

`AuthProvider` хранит информацию о текущем пользователе и предоставляет методы:

* `login`
* `register`
* `logout`
* `checkAuth`

При запуске приложения выполняется проверка авторизации.

Логика работы:

```text
Application starts
        ↓
Token exists?
   ↓          ↓
  No         Yes
   ↓          ↓
Guest      GET /auth/profile
               ↓
        Token is valid?
           ↓       ↓
          Yes      No
           ↓       ↓
       Restore    Logout
        user
```

---

## Защищённые маршруты

Для страниц, доступных только авторизованному пользователю, используется `ProtectedRoute`.

Пример логики:

```text
Protected Route
      ↓
Authentication loading?
      ↓
      Yes
      ↓
Show loading
      │
      No
      ↓
User exists?
   ↓          ↓
  No         Yes
   ↓          ↓
Redirect    Render
to public    page
page
```

# Backend Setup

Перейдите в папку backend:

```bash
cd server
```

Установите зависимости:

```bash
npm install
```

Создайте файл `.env`.

Пример:

```env
DATABASE_URL="postgresql://user:password@localhost:5432/todo"

PORT=5000

PRIVATE_KEY=your_secret_key
```

Выполните миграции Prisma:

```bash
npx prisma migrate dev
```

Запустите сервер:

```bash
npm run start:dev
```

API будет доступен по адресу:

```text
http://localhost:5000
```

# Аутентификация

Приложение использует JWT-аутентификацию.

После успешной регистрации или входа:

```text
User
   ↓
Login / Register
   ↓
Server
   ↓
Access Token + User
   ↓
Frontend stores token
   ↓
AuthProvider updates user
```

При последующем запуске приложения:

```text
Token
   ↓
GET /auth/profile
   ↓
Server validates JWT
   ↓
User restored
```

Если токен недействителен или истёк:

```text
Server returns 401 / 403
        ↓
Frontend removes token
        ↓
User becomes null
        ↓
Protected routes redirect user
```

# Обработка ошибок

На backend используется глобальный `ExceptionFilter`, который приводит ошибки к единому формату.

Пример:

```json
{
  "success": false,
  "error": {
    "statusCode": 404,
    "timestamp": "2026-08-01T13:45:00.000Z",
    "path": "/tasks/100",
    "method": "GET",
    "message": "Task not found"
  }
}
```

Это позволяет frontend получать ошибки в предсказуемой структуре.
